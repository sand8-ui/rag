# 账号、登录与 App 异常（客服排障）

文档编号：SW-SOP-APP-2026  
用户常把「系统问题」说成「酒店没收到预订」。先分清是账号问题还是订单问题。

## 1. 登录失败

| 现象 | 可能原因 | 客服怎么说 |
| --- | --- | --- |
| 提示邮箱或密码错误 | 邮箱输错、密码少于 6 位、记混账号 | 确认用的是注册邮箱。演示账号 guest@staywise.com / 123456 |
| 登录成功又跳回登录页 | access token 过期且 refresh 失败 | 再登录一次；清站点数据后再试 |
| 一直转圈 | 后端没开或 Docker 没开 | 开发演示：先确认 3001 能打开。对「真用户」话术则是系统繁忙请重试 |
| 跨设备登不上 | 记错邮箱 | 不要让用户用手机号登录，演示只支持邮箱 |

演示没有验证码、没有找回密码、没有短信。用户喊「收不到验证码」时说明本环境不发短信。

## 2. 登录了但订单是空的

- 用另一个邮箱注册过。请用户回想下单那天的邮箱。
- 订单被自己点过删除。演示是真删。
- token 属于 A 用户，浏览器里还残留期待 B 的单。退出后重登。
- 前端请求 401 后 refresh 失败，拦截器清了会话。再登录。

## 3. 下单按钮没反应 / 预订失败

按顺序问：

1. 有没有选入住离店？离店是否晚于入住？
2. 入住是否早于今天？早于今天前端不能选，强改接口会 400。
3. 人数是否大于房型最多人数？大床房 2 人、行政套房 3 人等。
4. 网络面板里 `/orders` 是 401 还是 400 还是 Failed to fetch？
   - 401：重新登录
   - 400：读 message
   - Failed to fetch：后端或 CORS（5173/5174）

## 4. 改期或删除失败

- 404：不是自己的单，或已经删了。
- 400：新日期不合法。
- 不要教用户改数据库。

## 5. 账号安全

- StayWise 员工不会打电话索要密码或短信验证码（演示也没有验证码）。
- 有人自称「酒店财务」让用户把房费打到个人微信：诈骗。让用户挂断，只通过 App 订单或酒店前台结账。
- 用户怀疑账号被盗：演示可让他改密码（若未做改密，则换新邮箱注册并作废旧会话——目前无改密则说明限制）。

## 6. 多端

同一账号可以在多处登录。后登录不会踢前一个（当前实现）。用户觉得「串号」多半是共用了浏览器。
